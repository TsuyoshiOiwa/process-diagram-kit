■ 作業の進め方
1. スコープを質問で確定 (貸出+予約分岐 / 利用者+図書館[カウンター・システム])
2. テンプレートをコピーしてフローのみ先に作成 (座標は仮置き)
3. PNG を生成 → 画像を確認 → top/left 調整、を反復 (1回1箇所ずつ)

■ うまくいったこと
- [反復レイアウト] 描画して目で確認するループが最短。
  tala の経路探索は予測が難しく、座標の机上計算では決めきれなかった
- [メッセージフローの縦揃え] プール間メッセージの両端ノードの left を
  揃えると縦直線になる (貸出依頼/予約申込/資料・カード/入庫連絡の4本を直線化)
- [詰みどころの外側配置] 「入庫連絡」はシステム(下レーン)→利用者(上プール)で
  カウンターレーンを横断する必要があり大回り経路になった。
  両端イベントをレーン幅の外側 (右端) に置いたところ直線化した
- [行の分離で交差解消] GTW-003001「不可」→貸出不可エンドの縦線と
  予約連絡チェーンの横線が交差 → 貸出不可をゲートウェイ直下 (1段目)、
  予約連絡チェーン (予約情報登録→入庫連絡送信→完了) を最下段へ移し交差ゼロ
- [レーン横断フローはプール階層に記述] シーケンスフローのレーン横断は
  プール直下にフルパスで書く (下記失敗参照)
- [ルート direction: down] プール縦積み + メッセージ縦流しに合い整列が美しくなった

■ うまくいかなかったこと
- [相対パス参照で意図しない箱が生成] レーン (ACT-002) ブロック内に
  「TSK-002005 -> ACT-003.TSK-003003」と書くと、ACT-002 の内側に
  ACT-003 コンテナが新規生成された (D2 はスコープ相対でキーを解決するため)。
  → プール階層に「ACT-002.TSK-002005 -> ACT-003.TSK-003003」とフルパスで移動
- [レーン順の入替は逆効果] システムレーンを上にすると入庫連絡は直線化するが、
  代わりに貸出依頼/予約申込/資料・カードが大回りした。元に戻した
- [空き通路でもレーン横断は迂回される] カウンターレーン内の空き列を通す経路でも
  tala はレーン境界の交差を嫌って外周へ大回りした
  (ノード衝突の回避だけでは直線化しないと分かった)
- [スクリプト一括置換の取りこぼし] python/sed での座標置換時、
  インデント違いで一部置換が無音で失敗した
  → 置換後は grep で反映を確認する習慣が必要

■ 最終レイアウトの規約 (メモ)
- 行: top = 0 / 320 / 640、列: left = 260 刻み + メッセージ用の専用列
- メッセージ用縦列: 貸出依頼 x=1120 / 予約申込 x=820 / 資料・カード x=2400 /
  入庫連絡 x=2900
- プール: PRM-001 利用者 (上) / PRM-002 図書館 (下)
  レーン: ACT-002 カウンター (3行) → ACT-003 システム (2行) の縦並び

■ 再利用スクリプト (本次作業で抽出)

    既存行は値だけ置換しインデントを維持、未存在ならノード定義直後に挿入。
    usage: python3 scripts/d2setpos.py works/foo.d2 NODE.top=320 NODE.left=820
           python3 scripts/d2setpos.py works/foo.d2 --unset NODE.top
- scripts/render.sh   : 単一 .d2 を tala+font で out/ に高速ビルド (確認用)。
    usage: ./scripts/render.sh works/foo.d2 [png|svg]
